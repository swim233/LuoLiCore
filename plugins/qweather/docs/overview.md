# 和风天气（qweather）

查询天气和天气预警的服务。数据覆盖全球，均按经纬度查询。

## 接口

- `city_lookup` 城市查询：把地名查成经纬度。其他接口都需要经纬度，通常先调用此接口。
- `weather_now` 实时天气：某个地点当前的天气。
- `weather_daily` 逐天预报：某个地点未来 1 到 10 天的预报。
- `weather_alert` 天气预警：某个地点正在生效的官方预警。

每个接口的参数和返回的字段各有一节，调用前先读对应的一节。

## 用法

1. 用户只给出地名时：先调用 `city_lookup` 查询经纬度。查到多个无法区分的地点时，列出候选（名称、上级行政区）让用户选择，不要猜。
2. 经纬度保留两位小数即可。`city_lookup` 返回的位数更多，四舍五入到两位后再使用，如 `39.91755` 写作 `39.92`；同一个地点每次使用相同的写法。
3. 返回数据含时间的接口必须带上 `localTime: true`，时间即为当地时间。不带时为 UTC，日期可能与当地相差一天，容易看错。
4. 本次对话中已查询过经纬度的地点直接沿用，无需重复查询。

## 注意事项

- 告知天气、预警时注明来源「数据来自和风天气」。告知预警时同时注明发布机构，如「上海中心气象台发布，数据来自和风天气」。这是使用此服务的条件。
- 预警可能有延迟，以官方发布的为准。
- 带单位的数值（气温、风速、降水量、气压、能见度等）均为 `{ value, unit }` 的形式。
- 湿度、云量、降水概率为 0 到 1 之间的小数，告知时换算成百分比。
- 语言默认为当地的官方语言，中国的地点为中文。查询国外的地点需要中文时，加上 `lang: "zh"`；预警的内容不一定有中文。
- 请求按次计费，每天有上限。不要为同一件事反复调用。
- 出错时会给出 HTTP 状态和原因，先看原因，不要原样重试：
  - 400：通常是参数有误（见 `error.invalidParams`），或者地点不存在、该地点没有数据（见 `error.title`）；
  - 401、403：账号或配置有问题，告知用户检查；
  - 429：请求过于频繁，稍后再试。
