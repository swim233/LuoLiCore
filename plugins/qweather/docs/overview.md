# 和风天气（qweather）

查天气和天气预警的服务。数据覆盖全球，都按经纬度查。

## 接口

- `city_lookup` 城市查询：把地名查成经纬度。别的接口都要经纬度，所以一般先调它。
- `weather_now` 实时天气：某个地点现在的天气。
- `weather_daily` 逐天预报：某个地点今后 1 到 10 天的预报。
- `weather_alert` 天气预警：某个地点正在生效的官方预警。

每个接口的参数和返回的字段各有一节，用之前先读那一节。

## 怎么用

1. 人只说了地名：先调 `city_lookup` 查经纬度。查到几个分不清的地方时，把候选（名字、上级行政区）列给人挑，不要自己猜。
2. 经纬度最多写两位小数。`city_lookup` 返回的位数更多，四舍五入到两位再用，如 `39.91755` 写成 `39.92`。
3. 返回里有时间的接口都带上 `localTime: true`，时间就是当地时间；不带是 UTC。
4. 这次对话里已经查过经纬度的地点接着用，不用再查一遍。

## 要注意

- 说天气、说预警时带一句来源「数据来自和风天气」。说预警时把发布机构也说上，如「上海中心气象台发布，数据来自和风天气」。这是使用这个服务的条件。
- 预警可能有延迟，以官方发布的为准。
- 湿度、云量、降水概率是 0 到 1 之间的小数，说的时候换成百分比。
- 语言默认是当地的官方语言，中国的地点是中文。查国外的地点想要中文，加 `lang: "zh"`；预警的内容不一定有中文。
- 请求按次计费，每天有上限。不要为同一件事反复调。
- 出错时会给 HTTP 状态和原因，先看原因，不要原样重试：
  - 400：多半是参数写错了（看 `invalidParams`），或者这个地点没有数据；
  - 401、403：账号或配置的问题，告诉人去检查；
  - 429：请求太频繁，过一会儿再说。
