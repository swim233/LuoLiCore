# 组件库 @luoli/ui：面板的组件抽成本仓库里的一个包，按源码引用

网页面板里的按钮、滚动、气泡、星空原来都写在面板自己的代码里：别的项目用不上，面板里同一种东西也有好几种写法（9 种按钮、十几种字号、89 种内边距）。用户希望把它们抽成组件库，以后别的项目能复用，各项目的样子统一。

## 怎么做

- **名字和位置**：包名 `@luoli/ui`，放在本仓库的 `packages/ui/`，是 pnpm workspace 里的一个包。面板按包名引用它的源码，不单独构建，不发布。
  - 没有总入口，按子路径引用（`@luoli/ui/controls`、`@luoli/ui/scroll`……）。入口加载时不碰 DOM：面板的测试在 node 里跑，引一个纯函数不会连带加载别的模块。
  - 库只引用包里自己的文件和自己声明的依赖；`src/` 下只有网页面板能引用它，而且只能按包名引用。由 lint 规则保证。
- **进库的层**：设计变量；基础控件和三种「面」；滚动；浮层；表单控件；聊天内容；特效。桌面外壳（窗口的形变、整理、胶囊、全屏）和状态徽记是这个面板独有的，留在面板。
- **样式**：纯 CSS，放进 `@layer`，类名以 `ll-` 开头，变量以 `--ll-` 开头、按用途起名。
  - 用它的项目自己的样式不放进层，天然盖过库的。所以库的样式里不写 `!important`：层里的 `!important` 反而比层外的强，项目就盖不过了。
  - 变化用 `data-*` 属性表示；颜色都是变量，样式里不写颜色字面值；悬停写在 `@media (hover: hover)` 里。
  - 总样式一份（`styles.css`）；聊天内容、特效的样式各是单独的一份，用到才引。
  - 变量和基础控件的样式不依赖框架，别的框架的项目引进去也能用；带行为的组件只有 React 版。
- **风格**：组件只认变量。夜蓝星空是默认的一套配色，现在只有这一套。
  - 原来的样子做过归并（按钮并成三类、各三档），数字吸附到一套刻度上（字号、间距、圆角、层级）。
  - 专门调过的地方留成有名字的专用值：气泡的字号和行高、渐进模糊的参数、窗口的圆角。
- **行为**：标签页、浮层、表单控件用 Base UI（`@base-ui/react`）打底，键盘走法、焦点、读屏属性、定位都由它给，样子自己做。版本写死。
- **动画**：库里只用 CSS 的过渡和动画，不依赖 Motion。动画开关在 `@luoli/ui/motion`（跟随系统、开、关）；库不存储，由用它的项目记住用户的选择。关动画时只剩很短的淡入淡出。
- **库不认识外壳**：库里的东西要知道外壳状态的地方，都由面板传进来或者调一下，比如「大动画在不在走」传给滚轮缓动和气泡外框的补间，形变开始时让悬停高亮收起。点名外壳状态的样式留在面板，对着库的类名写。
- **库不认识 AI SDK**：聊天气泡只收库自己定义的简单结构（文字、图片、思考、工具），角色叫别人、自己、助手。消息怎么变成这些结构，是用它的项目的事。
- **特效**：星空背景和星尘粒子在 Worker 里用 OffscreenCanvas 画。星空的 Worker 由库自己建；星尘的 Worker 由用它的项目建好传进来，面板让它和徽记共用一个。
- **图标**：部件图标、四角星是手写的；通用的图形从 Lucide 把 SVG 抄进库，线宽调成和手写的一家，不加依赖。
- **展示页**：库自己的开发入口（`pnpm ui:dev`），不经过面板，每个组件的各种状态都摆在上面。新的样子先在展示页里给用户看，定了再换到面板上。
- **测试**：纯逻辑写自动化测试；样子和交互由 QA 在展示页和面板上用真实浏览器验收。只搬代码、不改样子的步骤，拿面板和搬之前逐像素比。
- **依赖**：`react` 由用它的项目提供；库自己声明 `@base-ui/react`、`@tanstack/react-virtual`（长列表）、`marked`（Markdown 的词法分析，版本写死）。库不带字体文件，只定字体的变量。

## Considered Options

- **独立成仓库、发布到 npm**：现在只有面板一个使用者，发布、版本号、构建都是额外的事。等第一个外面的项目要用时再做。
- **先构建成产物再引用**：改一处要多等一次构建；面板的打包器本来就能直接处理源码。
- **一个总入口**：引一个纯函数会连带加载碰 DOM 的模块，面板在 node 里跑的测试就过不了。
- **CSS Modules**：类名由构建工具生成，肯定不撞名；但只能在 React 组件里用，别的框架的项目用不上。
- **Tailwind**：现有的几千行样式要重写一遍，毛玻璃、渐进模糊还是得写普通 CSS。
- **不用 `@layer`，靠选择器的权重**：面板要盖过库的样式就得比着权重写，外壳为形变写的规则会和库的打架。
- **浮层和表单的行为自己写**：焦点管理、键盘走法、读屏属性、定位避让是一大堆细节。
- **别的无头库**（定的时候是 2026-11，对比表在 `.grill/component-lib/brief-r2.md`）：
  - React Aria Components：toast 还在实验中，没有滚动区。
  - Radix：没有数字输入和带搜索的下拉，表单校验是预览版。
  - Ark UI：组件最全，但下一个大版本要改写样式用的属性名，现在接以后得迁一遍。
  - Headless UI：没有提示气泡、toast、滑块、数字输入，半年没有新版本。
  - Base UI 要用的组件都有，进出场默认是能中途反向的 CSS 过渡。风险是 1.0 才出不到一年，浮层套浮层还有没修完的问题。
- **外壳和徽记也进库**：它们和面板的状态缠在一起，别的项目用不上。
- **Storybook**：自己写的展示页够用，能垫星空、切动画开关和缩放，不多一批依赖。
- **图标库作为依赖**：只用十几个图形；抄进来才能把线宽调成和手写的一家。
- **库里用 Motion**：库里的动画用 CSS 就够了；Motion 留给外壳的形变。

## Consequences

- 样式分在两处：库的（在层里）和面板自己的（不在层里）。改一个控件的外观要去库里改，面板的样式里只给它们写布局。
- 库的类名和变量成了面板样式的依赖：库里改名，面板的 `app.css` 要跟着改，没有类型检查帮忙。
- 面板用上 Base UI 的浮层以后，JS 包大了约 160 kB（gzip 约 53 kB）。上公网时再看要不要拆包。
- Base UI 和 `marked` 的版本写死，升级要手动做、要过测试和验收。
- 表单控件现在只摆在展示页里，面板到第十阶段（设置的修改）才用上。
- 只有深色的一套配色，只管桌面 Chrome。
- 别的项目现在还不能直接装这个包；发布等有了第一个使用者再做。

## 不做

- Vue 版的组件、第二套配色（浅色）、Firefox 与 Safari。
- 发布到 npm、独立成仓库、单独构建。
- Storybook、组件的自动化测试（纯逻辑照旧写）、图标集作为依赖、Tailwind 的预设、库带字体。
- 导航类（面包屑、分页、步骤条）、数据展示类（数据表格、头像、点开看大图、树、键盘按键的样式）、布局和排版的组件、重型组件（日期时间选择、图表、命令面板、文件上传区、抽屉、右键菜单）。
